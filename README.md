# Club Connect v0.8

هسته‌ی پروکسی بدون نیاز به تنظیم. یک پورت واحد، هم **SOCKS5** (با UDP) و هم **HTTP proxy**.
آدرس پیش‌فرض: `127.0.0.1:1819`

> این برنامه یک **پروکسی** است، نه VPN سراسری. باید برنامه یا سیستم‌ات را روی آدرس بالا تنظیم کنی (پایین‌تر توضیح داده شده).

## کدام فایل را بگیرم؟

| سیستم | فایل |
|---|---|
| ویندوز ۶۴ بیتی (اکثر کامپیوترها) | `clubconnect-v0.8-windows-amd64.zip` |
| ویندوز ۳۲ بیتی | `clubconnect-v0.8-windows-x86.zip` |
| ویندوز ARM | `clubconnect-v0.8-windows-arm64.zip` |
| لینوکس | `clubconnect-v0.8-linux-amd64.zip` یا `linux-arm64` |
| مک (اینتل / M1 به بعد) | `clubconnect-v0.8-macos-amd64.zip` / `macos-arm64` |
| اندروید (Termux) | `clubconnect-v0.8-android-arm64.zip` (یا `android-armv7a` برای گوشی‌های قدیمی) |

نکته‌ها:
- در ویندوز ۳۲ بیتی و ARM فقط نوع WARP به اسم `wg` در دسترس است (برای بقیه‌ی نوع‌ها aether لازم است و برای این دو سیستم ندارد).
- در `linux-arm64` و `windows-arm64` فایل `tor` داخل zip نیست، پس حالت‌های Tor آنجا کار نمی‌کنند.
- مک: بعد از باز کردن zip یک‌بار این دستور را بزن: `xattr -d com.apple.quarantine clubconnect`
- iOS پشتیبانی نمی‌شود.

## شروع سریع (ویندوز)
1. zip را در یک پوشه باز کن.
2. روی `clubconnect.exe` دوبار کلیک کن. یک پنجره‌ی منو باز می‌شود. **چیزی خودش روشن نمی‌شود**؛ خودت حالت را انتخاب می‌کنی.
3. عدد `1` (Auto) را بزن و Enter. وقتی در لاگ نوشت healthy یا established یا bootstrapped، عدد `7` را بزن تا اتصال و IP خروجی تست شود.
4. برنامه‌ات (مرورگر، تلگرام، ...) را روی پروکسی بگذار:
   - **SOCKS5**: آدرس `127.0.0.1` و پورت `1819`
   - **HTTP**: آدرس `127.0.0.1` و پورت `1819`
5. برای خاموش کردن: `S` (توقف و ماندن در منو) یا `Q` (توقف و خروج).

اگر پنجره را ببندی یا `Q` بزنی، پروکسی هم خاموش می‌شود. کلید `0` فقط منو را می‌بندد و هسته‌ی روشن، روشن می‌ماند (با Enter منو برمی‌گردد).

در لینوکس، مک و اندروید همین کار را از ترمینال انجام بده: `./clubconnect`

## حالت‌ها (منو: ۱ تا ۶)

| کلید | حالت | معنی |
|---|---|---|
| 1 | Auto | بهترین هسته‌ی سالم (WARP / Psiphon / Tor) را خودش انتخاب می‌کند و اگر قطع شد عوض می‌کند |
| 2 | WARP | فقط WARP |
| 3 | Psiphon | فقط Psiphon |
| 4 | Tor | فقط Tor |
| 5 | WARP → Psiphon | Psiphon همه‌ی اتصال‌هایش را از داخل تونل WARP می‌زند |
| 6 | WARP → Tor | Tor از داخل تونل WARP به ریلی/بریج وصل می‌شود |

اگر شبکه‌ات مستقیم به Psiphon یا Tor اجازه‌ی اتصال نمی‌دهد، حالت ۵ یا ۶ را امتحان کن.
در حالت‌های زنجیره‌ای (۵ و ۶) فقط TCP استفاده می‌شود.

## نوع WARP
برای حالت‌های ۱، ۲، ۵ و ۶ بعد از انتخاب، لیست نوع‌های WARP نشان داده می‌شود (Enter = همان قبلی). انتخاب برای **هر حالت جدا** ذخیره می‌شود.

| نوع | چیست |
|---|---|
| `auto` | موج‌به‌موج امتحان می‌کند و اولین مسیری را نگه می‌دارد که واقعاً داده رد کند |
| `wg` | WireGuard داخلی، بدون هیچ چیز اضافه |
| `masque` | MASQUE روی HTTP/3 (UDP 443)، شبیه HTTPS |
| `masque-h2` | MASQUE روی HTTP/2 (TCP 443)، برای وقتی QUIC یا UDP بسته است |
| `gool` | WireGuard داخل MASQUE، با IP خروجی متفاوت |
| `gool-classic` | WireGuard داخل WireGuard |
| `mim` | دو هاپ MASQUE، با IP خروجی متفاوت |
| `wg-noize` | WireGuard با هندشیک مبدّل، برای شبکه‌های سخت‌گیر |

ترتیب `auto`: `masque-h2` ← `wg+masque` ← `gool+wg-noize` ← `mim` ← `gool-classic`. اگر موج اول جواب نداد، بعد از حدود ۵۵ ثانیه بقیه امتحان می‌شوند.

اگر شبکه‌ات کند است یا `auto` دیر وصل می‌شود، همان نوعی را که روی شبکه‌ات جواب می‌دهد (مثلاً `masque-h2`) دستی انتخاب کن.

## تنظیمات (منو: ۹)
- پورت پروکسی
- ریجن Psiphon (کد دو حرفی مثل `DE`، `US`، `NL`) و نوع پروتکل (`auto` / `cdn` / `direct`)
- نوع بریج Tor (`auto` / `obfs4` / `snowflake` / `meek` / `webtunnel` / `none`) و فایل بریج شخصی
- endpoint دلخواه WARP و ثبت دستگاه جدید WARP
- تنظیمات Aether: حالت اسکن (`turbo` تا `ironclad`)، نسخه‌ی IP (`4` / `6` / `both`)، `noize` و تکه‌تکه‌کردن TLS (`fragment`)
- لاگ کامل (نمایش همه‌ی اتصال‌های ناموفق)

همه‌ی انتخاب‌ها ذخیره می‌شوند و دفعه‌ی بعد همان‌طور می‌مانند. اگر تنظیمی را وسط اجرا عوض کنی، برنامه می‌پرسد الان دوباره راه بیفتد یا نه.
در منو، کلید Enter (بدون هیچ چیز) آخرین حالتی را که استفاده کردی دوباره روشن می‌کند.

## اجرا بدون منو
    clubconnect.exe -mode auto
    clubconnect.exe -mode warp@masque-h2
    clubconnect.exe -mode warp+tor -variant gool
    clubconnect.exe -port 2000
    clubconnect.exe -v                 (نمایش نسخه)

حالت‌های مجاز: `auto`، `warp`، `psiphon`، `tor`، `warp+psiphon`، `warp+tor`.
با `-menu` می‌توانی همراه `-mode` منو را هم ببینی.

## کنترل از بیرون (API)
فقط روی `127.0.0.1:8808` کار می‌کند:

    GET /status
    GET /start?mode=auto[&variant=masque-h2]
    GET /variants
    GET /stop
    GET /switch?backend=...
    GET /test

اگر در کانفیگ `api_token` بگذاری، باید هدر `X-Token` بفرستی.

## فایل کانفیگ (اختیاری)
بدون کانفیگ هم همه‌چیز کار می‌کند. اگر بخواهی، `config.example.json` را به `config.json` تغییر نام بده و کنار برنامه بگذار.
نکته‌ی امنیتی: پیش‌فرض فقط روی `127.0.0.1` گوش می‌دهد. اگر `listen` را روی آدرس دیگری بگذاری، حتماً `username` و `password` هم لازم است.

## پورت‌ها
پروکسی `1819`، API `8808`، هسته‌های داخلی `8801` تا `8899`.

## اگر مشکلی پیش آمد
- **ضدویروس بلاک کرد:** برنامه موقع اجرا فایل‌هایی مثل `aether.exe` را در پوشه‌ی داده‌ی خودش باز می‌کند. پوشه‌ی `%APPDATA%\clubconnect` را در ضدویروس استثنا کن.
- **وصل نمی‌شود:** از منو لاگ کامل (`9` سپس `A`) را روشن کن، یک نوع WARP دیگر امتحان کن (مثلاً `masque-h2` یا `wg-noize`) و دوباره با `7` تست کن.
- **WARP ثبت‌نام نمی‌شود:** در تنظیمات `9` را بزن تا دستگاه جدید ثبت شود، و مطمئن شو `fragment` روشن است.
- **Tor شروع نمی‌شود:** فایل `tor` باید کنار برنامه باشد (در zip هست، به‌جز لینوکس ARM و ویندوز ARM).

## تازه در v0.8
- **یک فایل، یک هسته:** aether، psiphon و پل‌های Tor داخل خود `clubconnect` هستند. لازم نیست جدا کنارش بگذاری. فقط `tor` جداست.
- **`masque-h2` اول:** حالت `auto` اول فقط `masque-h2` را امتحان می‌کند و بعد بقیه را.
- **پورت پیش‌فرض ۱۸۱۹.** اگر قبلاً پورت ۸۸۸۸ ذخیره شده بود، خودکار به ۱۸۱۹ می‌رود؛ پورتی که خودت انتخاب کرده‌ای همان می‌ماند.
- **هیچ‌چیز خودکار روشن نمی‌شود:** حالت را از منو انتخاب می‌کنی.
- **توقف واقعی:** با Stop یا عوض‌کردن حالت، اتصال‌های باز قبلی هم بسته می‌شوند.
- **امنیت API:** درخواستی که از صفحه‌ی وب داخل مرورگر بیاید رد می‌شود، پس سایت‌ها نمی‌توانند `/stop` یا `/switch` را صدا بزنند.
- **رفع باگ:** قفل شدن هسته‌ی بیرونی وقتی خروجی خیلی بلند می‌داد، و خراب‌شدن `settings.json` یا هویت WARP در قطعی ناگهانی.

## هسته‌ها
- **warp**: حساب رایگان خودکار؛ `wg` = WireGuard داخل برنامه (بدون root)، endpoint موازی، UDP، DNS با اولویت IPv4 و کش؛ بقیه‌ی نوع‌ها با aether
- **psiphon**: کانفیگ را خود برنامه می‌سازد. بایننری باید از fork مورد استفاده‌ی Aether ساخته شود (CI همین کار را می‌کند)
- **tor**: بریج‌های پیش‌فرض داخل برنامه است؛ `tor` و `lyrebird`/`snowflake-client` کنار برنامه یا در Tor Browser

پورت‌ها: پروکسی **1819**، API **8808**، هسته‌های داخلی از **8801–8899**.

## نقص‌هایی که نسبت به ایدر برطرف شد
- **ثبت‌نام دستگاه WARP**: اگر شبکه‌ات SNI شامل `cloudflareclient.com` را می‌بندد، ثبت‌نام قبلاً کلاً شکست می‌خورد. حالا سه مرحله دارد: مستقیم ← با تکه‌تکه‌کردن ClientHello (مثل `--fragment` ایدر) ← ثبت توسط خود aether و گرفتن هویتش.
- **UDP برای وارپ‌های ایدر**: کلاینت SOCKS5 UDP ASSOCIATE اضافه شد (DNS و QUIC از مسیر MASQUE/gool رد می‌شوند).
- **آدرس IP در SOCKS5**: قبلاً آدرس IP هم به شکل «اسم دامنه» به بالادست فرستاده می‌شد؛ حالا نوع صحیح (v4/v6) می‌رود.
- **انتخاب مسیر**: به‌جای یک endpoint ثابت، حالت `auto` مسیرها را با تست واقعی داده می‌سنجد (نه فقط هندشیک).
- هندشیک WireGuard قابل پنهان‌سازی شد (`wg-noize`) که با WireGuard داخلی ممکن نبود.
